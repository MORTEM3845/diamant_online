# Diamant Online

Веб-игра для совместных экспедиций в пещеру: **3–8 игроков, закрытые решения, пять походов и общий риск**. Создайте комнату, отправьте друзьям ссылку и решайте — идти дальше или возвращаться с добычей. Для знакомства с игрой есть боты.

Это неофициальная цифровая адаптация механик **Diamant** Алана Р. Муна (**Alan R. Moon**) и Бруно Файдутти (**Bruno Faidutti**). Реализованы три явно разделённых набора правил. Иллюстрации веб-версии созданы специально для проекта; изображения карт и оформление издателей не используются как игровые ассеты.

![Вход в пещеру — оригинальная иллюстрация проекта](public/art/cave-entrance.webp)

## Что работает

- Комнаты с шестизначным кодом, приглашением по ссылке, выбором персонажа и готовностью игроков.
- Игра с друзьями, добавление ботов в лобби и отдельная тренировка.
- Скрытый одновременный выбор: решения раскрываются только после подтверждения всех исследователей в пещере.
- Деление сокровищ и остатков на пути, реликвии, повторные опасности, пять экспедиций, финальный подсчёт и реванш.
- Сохранение комнаты на сервере и возвращение на своё место после обновления страницы.
- Русский интерфейс, адаптивная вёрстка для телефона и компьютера, справочник правил и журнал экспедиции.

Сервер определяет колоду и результаты. Браузер отправляет действие игрока и получает только доступную этому игроку информацию.

## Редакции правил

| Режим в лобби | Код | Начальная колода | Реликвии |
| --- | --- | ---: | --- |
| Классика | `classic` | 30 карт | Нет |
| С реликвиями | `relics` | 31 карта | По одной перед каждым походом: **5, 7, 8, 10, 12** |
| Редакция 2016 | `legacy` | 35 карт | Все пять с начала игры; первые три спасённые за всю партию стоят по **5**, остальные по **10** |

Во всех режимах 15 карт сокровищ: `1, 2, 3, 4, 5, 5, 7, 7, 9, 11, 11, 13, 14, 15, 17`. Опасностей пять видов, по три экземпляра каждого.

При возвращении остатки **со всей тропы складываются**, затем делятся между возвращающимися. Один возвращающийся забирает все открытые реликвии; несколько одновременно не получают ни одной. Открытые и не спасённые реликвии удаляются после экспедиции, неоткрытые остаются в колоде. При повторе опасности одна карта этого типа навсегда исключается. Равенство итоговых очков означает общую победу.

Подробная сверка с первоисточниками и разбор пограничных случаев: [аудит правил](docs/research/rules-audit.md).

## Локальный запуск

Нужен **Node.js 22.12 или новее** и npm. Для локальной игры вход в Cloudflare не требуется.

```bash
npm ci
npm run dev
```

Откройте [http://localhost:5173](http://localhost:5173). Команда собирает интерфейс, применяет миграции к локальной D1 и запускает Worker через Wrangler. Локальная база хранится в `.wrangler/`; данные не отправляются в производственную базу.

`npm run dev` использует предварительную сборку. После изменения исходников остановите процесс и запустите его снова. Если нужен другой порт, задайте переменную окружения `PORT`.

Для проверки реального обмена между игроками используйте разные браузеры или отдельные профили. Вкладки одного профиля разделяют `localStorage` и возвращают вас на одно и то же место в комнате.

### Полезные команды

| Команда | Результат |
| --- | --- |
| `npm run check` | Проверка TypeScript, тесты, сборка |
| `npm test` | Тесты правил и API с настоящей локальной D1 через Miniflare |
| `npm run test:watch` | Тесты в режиме наблюдения |
| `npm run build` | Сборка клиента и серверного артефакта в `dist/` |
| `npm run db:migrate:local` | Миграции только локальной базы |
| `npm run references` | Загрузка официальных PDF в локальную папку `references/` |

Тесты проверяют деление остатков, варианты реликвий, утрату добычи, удаление опасностей, секретность решений, права игроков, конкурентные запросы и повторную отправку действий. Проверки не заменяют нагрузочный тест и проверку конкретного производственного аккаунта.

## Публикация в своём Cloudflare

Используются **Cloudflare Workers + Static Assets + D1**. Отдельный VPS и постоянно работающий Node-сервер не нужны.

```bash
npm ci
npx wrangler login
npm run deploy:setup
npm run deploy
```

1. `wrangler login` открывает авторизацию Cloudflare на вашем компьютере.
2. `deploy:setup` использует авторизованный Wrangler, находит или создаёт выделенную D1 для проекта и записывает её ID в `wrangler.jsonc`.
3. `deploy` выполняет проверки, применяет миграции к удалённой базе и публикует Worker вместе с интерфейсом.
4. Wrangler выводит адрес опубликованной игры. Проверьте создание комнаты и присоединение из второго браузера.

Идентификатор `00000000-0000-0000-0000-000000000000` в исходном конфиге — заглушка для локальной разработки. Для публикации сначала выполните настройку. ID аккаунта и базы не являются паролями; API-токены и содержимое `.dev.vars` нельзя добавлять в Git.

### Автопубликация из GitHub

После первой настройки базы добавьте в репозитории GitHub, в **Settings → Secrets and variables → Actions**:

| Тип | Имя | Значение |
| --- | --- | --- |
| Secret | `CLOUDFLARE_API_TOKEN` | API-токен с правами публикации Workers и работы с D1 в вашем аккаунте |
| Variable | `CLOUDFLARE_ACCOUNT_ID` | ID аккаунта Cloudflare |
| Variable | `CLOUDFLARE_D1_DATABASE_ID` | ID базы, подготовленной для этой игры |

Workflow публикации запускается при изменениях в `main` или вручную через **Actions → Run workflow**. Он проверяет проект, подставляет идентификаторы, применяет миграции и публикует текущую версию. Настройка секретов нужна для GitHub Actions; локальная авторизация Wrangler не передаётся в GitHub автоматически.

## Как подключаться и продолжать партию

- Создайте комнату и отправьте друзьям ссылку вида `/room/ABCDEF`. Ссылка содержит код комнаты, но не личный токен игрока.
- Каждый участник выбирает имя, персонажа и нажимает готовность. Организатор запускает партию, когда готовы все и за столом 3–8 мест, включая ботов.
- После подтверждения выбор изменить нельзя. Он остаётся скрытым до общего раскрытия.
- После похода **любой участник-человек** может начать следующую экспедицию. Добавление и удаление игроков в лобби, выбор правил и реванш остаются у организатора.
- Обновление страницы восстанавливает место в том же браузере. Не очищайте данные сайта во время партии: без сохранённого токена автоматически восстановить прежнее место невозможно.
- Во время похода нет таймера и автоматического ухода. Если участник потерял связь, партия ждёт его решения; он может переподключиться. Закрытие вкладки не превращает игрока в бота и не меняет его решение.

Сундуки соперников закрыты до финала. Свой счёт, открытая добыча и спасённые реликвии видны. Это выбранный вариант отображения сундуков; современный буклет не требует скрывать итоговые суммы.

Комнаты хранятся **семь дней после последнего сохранённого действия**. Обычный просмотр комнаты срок не продлевает. В `wrangler.jsonc` срок задаётся переменной `ROOM_TTL_HOURS`; плановая очистка удаляет истёкшие комнаты.

